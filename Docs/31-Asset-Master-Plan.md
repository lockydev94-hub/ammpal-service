## 1. Scope of this document

`31` decides **what gets made, in what order, by whom, and at what cost boundary**. It does not decide
what things look like (`30`), does not hold the export schema (`32`), does not list screens
(`33`), and does not hold the wording anyone sends to a generation model (`34` — one home for the
prompts, so a style change is made once). Every row of the inventory carries a `doc_ref` naming the
document section that makes the
asset necessary; **a row without a `doc_ref` is an invention and is refused by the validator.**

either a bundle path or an explicit CSP/bucket amendment, and that is `OD-DOC-26`.

## 6. Storage layout

`design-assets/` is created with the eleven sections from the brief. Deviations, each deliberate:

- **`03-customer-app/onboarding/` is reserved, not used.** The customer app's documented entry is OTP
  login with a language pick (`12` §3.2 screen 1); there is **no documented onboarding flow**. The
  multi-step onboarding with KYC upload belongs to the **partner** app (`12` §4.2 screen 1, `23` §8),
  so onboarding illustration demand is in `04-partner-app/`.
- **`06-partner-dashboard/` is created empty.** `12` §1 and `ADR-021` make the surface conditional and
  its scope open; producing assets for an unapproved surface is scope creep.
- **`07-motion/` is created empty by design.** `30` §7 is compositor-only motion; the only motion
  payload that could live here is an app splash, and no document specifies one.
- **`masters/` and `exports/` are created per section when the first asset lands**, not as empty
  directories. Approved originals stay separate from optimised production output (`10` of the brief),
  and the export step is regenerable, so only masters need to be preserved.
- **No `source-code/` directory is created.** `14` §2 and `08` §9 already define the repository layout
  as `apps/ · packages/ · docs/ · infra/ · scripts/`, and whether it is one monorepo at all is open
  (`OD-14-01`, `OD-14-03`, `OD-14-04` — all `[BLOCKER]`). Creating a wrapper folder would pre-empt a
  blocker and put the real layout out of step with `14`. Front-end assets will live inside the app
  packages once that decision is made; `design-assets/` holds masters, not shipped code.

**Version control arrived on 2026-10-21; the hash record stays.** This workspace was **not** a git
repository when this plan was written, which is why `asset-manifest.json` records `sha256_16`, byte size and
measured pixel dimensions for every file that exists, and `validate_assets.py` fails if the hash on
disk no longer matches the record. It **is** one now — `git init` was performed at the owner's direction
with a documentation-only baseline (`README` §16). That does **not** retire the recorded hashes: git
proves a file changed, while `sha256_16` plus measured bytes and pixels prove the *export* is the one the
document describes, which is the check `32` §4 actually runs. What git does newly enable is the rest of
the recommendation, still **not performed**: `git lfs` before the first binary master is produced.

imagery when the upload and storage system exists. `30` §5.3 is therefore the current route for all 24
generatable rows, and the raster batches above stay unrun until `OD-DOC-34` `[BLOCKER]` closes — there is
no point producing artwork that has nowhere lawfully to be served from. **Prompt wording lives in `34` and
nowhere else** (`DEC-01`): this document plans the work, `34` states what to send a model, and neither
duplicates the other.

## 8. What will not be produced

Each of these is refused by rule, not by taste — and each is a documented obligation elsewhere:

- **No invented people** as registered partners (`09` §4.4, `01` FR-CAT-05 real `photo_url`).
- **No fabricated reviews, ratings, "verified" badges, legal badges, GST numbers or certificates**
  (`26` §2 evidence rules; the suite's standing no-invention constraint).
- **No fake payment receipts, invoices or settlement statements.** Invoice and statement formats are
  specified in `07` §7.6 and `09` §4.10; a mock that looks like a real `INV-…` or `STL-…` document is a
  forgery with a plausible number on it.
- **No simulated app screenshots** for stores, marketing or "design approval" decks.
- **No text baked into illustrations** — three locales at 30 % expansion (`12` §8 i18n-03) would need
  three exports of every image, and Odia glyphs in a rasterised layout are unverifiable.
- **No real customer locations** in any demo, sample or marketing map render (`09` §8 marks job media
  `PERSONAL`).
- **No reuse of the four ChatGPT reference images** in product surfaces while `OD-COM-12` is open.
